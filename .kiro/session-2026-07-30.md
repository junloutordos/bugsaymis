### 4. Compliance-Mode Grading (Values Education)
- **Requirement:** Values Education is graded by checkbox compliance (did the student do the activity?), not numeric score — output is a completion % + qualitative remark ("Completed"/"Not Completed") at both quarter and school-year level. User explicitly asked for the threshold and school-year rule to be **dynamic/configurable**, not hardcoded.
- **Design:** `grading_options.grading_mode` (`numeric`/`compliance`) + `compliance_pass_threshold` (0–1) + `compliance_sy_rule` (`all_quarters_pass`/`average_threshold`) + `compliance_pass_label`/`compliance_fail_label` — all editable per-option through the existing Grading Option manager UI, no new admin page needed.
- **Key additions:**
  - `GradeComputationService::computeComplianceCategory()` / `computeFullComplianceClassRecord()` / `computeComplianceSchoolYearRemark()` — reuse the exact same weighted category-sum math as numeric grading (`computeCategoryScore()`); only the output differs (% + remark vs. GE + adjectival). No running-grade carry-forward in compliance mode — each quarter stands alone.
  - `computeComplianceSchoolYearRemark()`: under `all_quarters_pass`, ANY quarter missing threshold (or ungraded/null) fails the whole year even if the other 3 pass. Under `average_threshold`, the average must clear the bar AND all 4 quarters must be present — a missing quarter blocks "Completed" under both rules (fail-closed, never silently reads incomplete data as done).
  - `grading_mode` is **locked once the option has assessments recorded under it** — same reasoning as `ClassRecord::canChangeGradingOption()` (redefining what a "score" means after data exists would corrupt it).
  - `ClassRecordQuarterController::grades()` and `ClassRecordFinalGradeController` both branch on `grading_mode`, returning `gradingMode: 'compliance'|'numeric'` in the response so the frontend knows which shape it got.
  - Frontend: Grading Option editor gets a Numeric/Compliance toggle + threshold%/SY-rule/label inputs; `ScoreGrid.vue` renders checkboxes instead of number inputs and Compliance %/Remarks summary columns; `Show.vue`'s final-grades modal shows Q1–Q4 %/Average %/Remark instead of GE columns.
  - PDF (`ClassRecordPdfService`) and Excel (`ClassRecordExcelService`) exports both render a ✓/blank grid with the same compliance summary — smoke-tested end-to-end with real data (not just lint-checked).
- **Tests:** 14 new unit tests on `GradeComputationServiceTest` (23 total), 9 new feature tests in `ClassRecordComplianceGradingTest` — including the specific scenario proving `all_quarters_pass` and `average_threshold` actually produce different results for the same data (one weak quarter that fails under strict-per-quarter but passes under averaging).
- **Commit:** `5bbb4c57`.

## Key Patterns Learned This Session
- **Always add new columns to a model's `$fillable` array, not just the migration** — this bit twice in one session (`Subject.subject_group`, `ClassRecordAttendanceDate.subject_id`). Eloquent silently drops unlisted fields on mass-assignment with no error/warning; only caught via feature tests asserting the actual persisted value, not just "the request returned 200."
- **`gh run watch <run-id> --exit-status`** is the reliable way to monitor an in-flight GitHub Actions deploy from the CLI instead of polling ECS blindly — shows per-step progress and blocks until done.
- **Blue/green ECS deploys take ~10 min minimum** (bake-time alarm window: `crcmis-bg-target-5xx`/`crcmis-bg-elb-5xx`) even after the image is built and pushed — `describe-services` right after a push will still show the OLD task definition as PRIMARY for several minutes; don't conclude a deploy failed just because the revision number hasn't moved yet.
- **A grading option's "mode" (numeric vs compliance) is exactly analogous to its "grading option" assignment on a class record** — both get locked once real data exists under them, for the same reason (redefining what a score means mid-stream corrupts already-entered data). This pattern is now used in three places: `ClassRecord::canChangeGradingOption()`, and the new `grading_mode` lock in `GradingOptionController::update()`.
- **When a user asks for something to be "configurable," prefer per-row settings on an existing model over a new global settings table** — `stanine_lookup` (global, seeded once, no admin UI) was the wrong pattern to copy for compliance thresholds; putting `compliance_pass_threshold`/`compliance_sy_rule`/labels directly on `grading_options` let the feature reuse the existing Grading Option manager UI/permissions with zero new infrastructure.
- **A column existing in `$fillable` + migration is not proof it's actually used** — `applicable_employment_types` on `leave_types`/`allowance_types` had been populated by every seeder entry since the table was created, looked fully wired, but was never once read by any controller or Vue file (write-only/decorative data). Before assuming a field enforces something, grep for reads of it specifically, not just writes.
- **A boolean "flag" column on a type/config table doesn't guarantee the code that should check it actually does** — `leave_types.is_deductible` was `false` for WL yet `LeaveCreditService::applyLeaveDeduction()` deducted from it anyway, because that method never branches on the flag at all (it only gates a pre-filing UI warning in the controller). Always trace a flag to its actual read site before reasoning about what changing it will do.
- **When a merge conflict involves an unfamiliar file/feature, check commit lineage (parent hashes, timestamps, message) before picking a side** — resolving `Students/Index.vue`'s debounce-watcher conflict by guessing would have been a coin flip; `git log`/`git show` on both sides' originating commits made it unambiguous which one was the deliberate, newer fix.
- **Before deploying to production, distinguish "empty leave_credits row" from "leave type doesn't exist" from "leave type exists but nobody granted the employee a balance"** — three different failure modes that all look like "the balance doesn't show up," but only the third was HR's actual gap (FL/SPL existed and were filable, just never initializable).
