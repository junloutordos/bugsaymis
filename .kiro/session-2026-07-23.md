### 1. Class Schedule Print — Short/ILP Cells Always Show Time
- **Problem:** `.schedule-print-event` time was hidden below 40 min duration — ILP sessions and other short entries never showed their time on printed schedules. Fixed font size for all cells regardless of available height.

### 2. Faculty Official Time & Lunch — Sync from HR-Approved Work Schedule
- **Problem:** Print sheet's Official Time/Lunch summary rows read from `teacher_official_times`, a table with **no submission UI anywhere** — silently defaulted to 07:30–16:30 for everyone. Lunch specifically was never persisted; it was *guessed* client-side from free gaps in the class calendar.
- **Root cause:** Two disconnected systems — the real HR-approved schedule (`employee_schedules.daily_schedules`, submitted via My Work Schedule) vs. the vestigial `teacher_official_times` that print/scheduler actually read.
- **Fix:**
  - Migration: nullable `lunch_start`/`lunch_end` added to `teacher_official_times` (additive, backward-compatible)
  - New `App\Services\FacultyLoading\TeacherOfficialTimeSyncService::syncFromEmployeeSchedule()` — upserts `teacher_official_times` per day from `daily_schedules.{day}.time_in/time_out/lunch_start/lunch_end`
  - Hooked into `EmployeeScheduleController::approveSubmission()` and `::assign()` (HR bulk preset assignment) — both approval paths now sync
  - New command `faculty-loading:backfill-official-times` for schedules approved before this change
  - Print sheet's Lunch Time row now reads the real synced value (`—` when a day has no lunch recorded) instead of guessing
  - Added "My Official Time & Lunch" read-only banner to My Faculty Schedule (self view), sourced the same way
- Files: `app/Services/FacultyLoading/TeacherOfficialTimeSyncService.php` (new), `app/Console/Commands/FacultyLoading/BackfillTeacherOfficialTimes.php` (new), `database/migrations/2026_07_23_110000_add_lunch_to_teacher_official_times_table.php` (new), `app/Http/Controllers/HR/EmployeeScheduleController.php`, `app/Http/Controllers/FacultyLoading/ClassScheduleController.php`, `app/Models/FacultyLoading/TeacherOfficialTime.php`, `resources/js/Components/FacultyLoading/SchedulePrintSheet.vue`, `resources/js/Pages/FacultyLoading/Schedules/Index.vue`

### 3. Faculty Lunch — Plot as a Visible Band (Print Grid + Calendar)
- **Problem:** Even after #2 synced real lunch data, it only showed as text (summary row / banner) — never plotted as a visual band in the schedule grid, unlike sections (which get grade-level Lunch/Recess bands).
- **Root cause A (print):** `buildPrintSheet()` only builds `dayConfigs` (the band layer) when a grade level is passed. Faculty print sheets pass `$gradeLevel = null` by design (one teacher can span several grades) — so the grid never got any bands at all for faculty.
- **Root cause B (calendar):** `dayConfigFor()` for the By-Faculty/My Faculty Schedule view resolved Lunch from `groupHeaderInfo(groupId).grade_level` — a heuristic grade guessed from whichever subject the teacher happens to teach, not the teacher's own official time.
- **Fix:**
  - New `facultyOfficialTimesBulk(array $facultyIds)` — one batched query for many faculty (`facultyOfficialTimes()` now delegates to it)
  - `buildPrintSheet()`: when `$gradeLevel` is null but `officialTimes` is present (faculty sheets), builds a synthetic `{type: 'LUNCH', label: 'Lunch', start, end}` band per day from the faculty's own synced lunch — no band on days with none recorded
  - `renderCalendar()`: computes `officialTimesByFaculty` (batched, keyed by faculty user id) and sends it alongside `myOfficialTimes` (which now reuses the batch)
  - `dayConfigFor()` in `Index.vue`: for `viewBy === 'faculty'`, strips the borrowed grade's `LUNCH`/`WHITE_SPACE`/`WELLNESS`/`CONSULT` bands and replaces Lunch with one built from the specific teacher's own official time
  - Band carries no `write`/`sectionEditable` marker → renders display-only automatically (existing `isBandDraggable`/`isBandClickable` logic already gates on those) — official time changes only happen via My Work Schedule, not calendar drag
  - Section-view logic in `dayConfigFor()` untouched — no regression risk to existing grade-level Lunch/Recess bands
- Files: `app/Http/Controllers/FacultyLoading/ClassScheduleController.php`, `resources/js/Pages/FacultyLoading/Schedules/Index.vue`

## Key Patterns Learned This Session
- `teacher_official_times` has no submission UI — it's a derived/synced table now, populated only via `TeacherOfficialTimeSyncService` at HR approval time (submission or bulk assign). Never edited directly.
- Faculty-scoped bell-schedule bands (Lunch specifically) can't reuse the grade-level `dayConfigsByGrade` mechanism for a faculty view — a teacher's real official time is per-person, not per-grade. Any future faculty-specific band (e.g. a personal break) should follow the same pattern: batch-fetch by faculty id, inject into `dayConfigFor()`'s `viewBy === 'faculty'` branch, omit `write`/`sectionEditable` to keep it display-only.
- `groupId` **is** the faculty user id when `viewBy.value === 'faculty'` (confirmed via `groupHeaderInfo`/`unplacedLoads` matching) — safe to key any per-faculty batched prop by it directly.
- Dev DB (`bugsaymis` in the `php` container) has no seed data (0 users) — verification of user-scoped features requires creating temporary test records via `tinker` and cleaning them up after. Always double-check cleanup fully removed prior sessions' leftovers too (found and removed a stray `qa-lunch-test@example.test` user left over from an earlier verification pass).
